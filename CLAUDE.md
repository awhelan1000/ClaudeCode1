# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A workshop repository ("Claude Code, zero to expert") built around one sample app:
**ops-dashboard**, an operations dashboard for a fictional company, Marlowe & Finch.
Java/Spring Boot backend + plain-JS frontend, no framework, no build step for the
frontend. Workshop material (labs, tickets, docs) lives alongside the app; see
`README.md` for the full picture.

## Commands

```bash
# Backend
docker compose up -d db            # PostgreSQL 16 on localhost:5432 (db/user/pass "ops")
./mvnw spring-boot:run              # run with Postgres, http://localhost:8080
SPRING_PROFILES_ACTIVE=demo ./mvnw spring-boot:run   # run with in-memory H2, no Docker needed
./mvnw test                         # Java tests (JUnit 5, always run on the demo/H2 profile)
./mvnw test -Dtest=DashboardRepositoryTest            # single test class
./mvnw test -Dtest=DashboardRepositoryTest#kpisForTheLast30DaysMatchTheAnswerKey  # single test method

# Frontend
npm install                         # once
npm test                            # Jest + jsdom
npx jest src/test/javascript/range.test.js            # single test file
npx jest -t "the 7-day preset"                        # single test by name
```

There is no linter configured for either side.

## Architecture

**Backend** (`src/main/java/com/marlowefinch/ops/`): Spring Boot, Spring JDBC with
hand-written SQL (no JPA), Flyway migrations. Controllers (`KpiController`,
`DeliveryController`, `TicketController`, `VendorController`, `HealthController`) are
thin and delegate to two repositories: `DashboardRepository` (KPIs, on-time rate, late
deliveries, tickets) and `VendorRepository` (vendors + days-until-contract-end). All
endpoints are read-only `GET` under `/api`, returning records (`Kpis`, `CarrierOnTime`,
`LateDelivery`, `TicketCategoryCount`, `Vendor`).

- **`DateRange`** resolves `from`/`to` query params, defaulting to "last 30 days ending
  today." Deliberately unvalidated: a malformed date 500s, `from` after `to` yields an
  empty result. This is intentional current behavior, tracked as `docs/tickets/TODO-232.md`
  — don't "fix" it unless that's the task.
- **`ClockConfig`** pins the app's notion of "today" to `2026-09-21` (property
  `ops.today`) via a fixed `Clock` bean, rather than reading the system clock. Every
  default date range, every "days until renewal" figure, and every test assertion is
  computed from this bean. This is why tests can assert exact numbers instead of ranges.
- Two Spring profiles: `postgres` (default, real Postgres via `docker-compose.yml`) and
  `demo` (H2 in PostgreSQL-compatibility mode, same Flyway migrations/seed, no Docker).
  Tests and Claude Code on the web always use `demo`.
- Seed data is generated by `tools/make_seed.py` into `V2__seed.sql`, and mirrored into
  `docs/data/deliveries-last-30-days.csv` and `docs/data/ANSWER-KEY.md`. Expected test
  figures (revenue, on-time rates, counts) are cross-checked against the answer key —
  if you regenerate the seed, the answer key and both test suites need updating too.

**Frontend** (`src/main/resources/static/`): `app.js` is vanilla JS exporting
`initApp(document, fetchImpl)` plus pure helper functions (`formatRate`, `formatMoney`,
`barWidths`, `applyPreset`, `daysUntil`) that are unit-tested directly. It fetches
`/api/health` first, then the four range-dependent endpoints plus `/api/vendors`, and
renders four KPI tiles and two charts as inline SVG (no charting library), a late-
deliveries table, and a vendor-renewal list.

**Frontend test harness** (`src/test/javascript/setup/loadApp.js`): loads `index.html`
into jsdom, replaces `fetch` with an in-memory fake of every `/api` endpoint (fixtures
match the same answer key as the Java tests), and requires `app.js` fresh per test via
`jest.resetModules()`. It maintains `REGISTERED_IDS`, the list of every element id the
tests know about; `harness.test.js` asserts `index.html` and `REGISTERED_IDS` stay in
sync. **Any new interactive element id added to `index.html` must be added to
`REGISTERED_IDS` in `setup/loadApp.js`**, or the harness test fails.

Two test suites verify the same seed data from opposite ends of the stack (SQL/API
correctness in Java, rendering/interaction correctness in Jest) — see `README.md`'s API
table and tree diagram for endpoint/file details rather than duplicating them here.

## Constraints

- `pom.xml` dependencies are frozen. Any change requires a CHG ticket (see comment at
  the top of `pom.xml` and `docs/PRE-WORK.md`).
- There is deliberately no `.mcp.json`-independent database access assumed: the
  `postgres` MCP server in `.mcp.json` is read-only (queries run in a `READ ONLY`
  transaction) and only relevant when Docker/Postgres is running.
